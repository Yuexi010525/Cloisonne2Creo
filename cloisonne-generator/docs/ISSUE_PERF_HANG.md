# 复杂彩色图分析卡死/内存爆炸 — 根因与修复

日期：2026-09-04
状态：已修复并实测（提交中）
报告人：豆包（执行端）
复现图：用户上传的 750×751 彩色卡通涂鸦图（183 色，细碎元素多）

## 1. 问题现象

对**复杂彩色图**（多色、细碎元素多）做彩色掐丝分析时：
- 分析长期停在"正在分析..."（>40s 仍无结果）
- 服务进程内存飙到 **770MB** 且不回落
- `/api/health` 不响应（服务假死），需手动 kill

用户反馈"越做越烂"的直接原因：V2.3 期间为功能加了多个处理阶段，但**性能上仍是朴素 O(N²) / 无上限递归**，简单测试图（test01-04）掩盖了问题，一旦遇到真实复杂图就卡死。

## 2. 根因定位（faulthandler 逐点定位）

用 `faulthandler.dump_traceback_later` 在超时后 dump 调用栈，逐次定位到 **4 个热点**：

| # | 位置 | 问题 |
|---|---|---|
| 1 | `backend/boundary/shared_boundary.py` `_prune_overlap` | 对**每条闭合边界**都对"其余所有边界"做 `unary_union + buffer`（shapely 重操作），朴素 O(N²)，复杂图边界多时爆炸 |
| 2 | `backend/curve/simplifier.py` `_douglas_peucker` | 纯 Python 递归 + 逐点距离计算，容差小时几乎不简化 → 最坏 O(n²) |
| 3 | `backend/curve/bezier_fitter.py` `_fit_curve` | 递归拆分**无段数上限**（max_segments 参数定义了但从未使用），深度爆炸；距离计算每次新建 numpy 数组 |
| 4 | `backend/curve/curve_merger.py` `merge` | 对每条曲线扫描**所有其他曲线**做 4 种 G0/G1 检查，O(N²) 全量扫描，且内层反复重算端点/切线 |

## 3. 修复（保持输出完全一致）

| 位置 | 修复 |
|---|---|
| `_prune_overlap` | 用 **shapely STRtree 空间索引**，只对与当前边界相交/邻近的候选做 union+buffer；加闭合边界数保护（>400 跳过） |
| `_douglas_peucker` | **numpy 向量化**区间距离计算（一次算整段最远点）；点数 >2000 均匀抽稀；递归深度上限 500 |
| `bezier_fitter.fit` | 点数 >1000 均匀抽稀（保留首尾）；`_fit_curve` 真正执行 **max_segments=50 硬上限**；点到贝塞尔距离**向量化**（预计算控制点，采样 12） |
| `curve_merger.merge` | **端点网格索引**：只检查端点距离 ≤ g0_tolerance 的邻域候选（结果与全量扫描一致）；端点/切线预计算 |

## 4. 验证

**性能**（同一张 750×751 复杂卡通图）：
- 修复前：>40s 卡死，内存 ~770MB
- 修复后：**15.7s 完成**（regions=547 / boundaries=934 / merged=860）

**回归（简单图输出必须不变）**：
- 彩色回归 `scripts/test_color.py`：Test01 2/1/1、Test02 4/5/5、Test03 花 14/20/20、Test04 猫 15/21/21、TestPattern 3/3/3，自交全部 0 —— **与 V2.3 基线一致**
- 线稿回归 `scripts/test_lineart.py`：粗直线/粗圆环 skan=1 条单中心线、粗十字 skan=4、用户线稿 skan=173 —— **与 V2.3 基线一致**

## 5. 结果质量说明（非本次修复范围，供 ChatGPT/用户决策）

这张图即使修复性能，默认参数（颜色精度 6 / 斑点过滤 4）仍产生 **934 条边界 / 2163 个线距冲突**——因为图本身 183 色、细碎元素太多，细分过头。

实测参数对比（HTTP API 同一张图）：

| 颜色精度 | 斑点过滤 | 区域 | 边界/曲线 | 耗时 |
|---|---|---|---|---|
| 6 | 4（默认） | 547 | 934 / 860 | 15.7s |
| 4 | 8 | 490 | 863 / 820 | 13.1s |
| 3 | 8 | 342 | 593 / 563 | 8.5s |
| 3 | 12 | 262 | 511 / 481 | 7.1s |
| 2 | 10 | 7 | 6 / 6 | 1.1s（过度简化，丢失细节） |

结论：**这类"插画风涂鸦"（细碎装饰元素多、颜色杂）不适合高密度掐丝**。建议：
1. 工具层面：对复杂图默认给更保守参数（如颜色精度 3~4、斑点过滤 10+），或增加"简化"预设
2. 用户层面：掐丝更适配大色块、清晰轮廓的图案；装饰插画建议先做图像简化
3. 是否调整默认参数需 ChatGPT 拍板（避免破坏 test01-04 基线）
