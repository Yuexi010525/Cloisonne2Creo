# Cloisonne2Creo V2.1 线稿模式 — 实施报告

> 对应规格书：`开源掐丝模型生成器推荐-4.html`（ChatGPT V2.1 线稿模式指令）
> 解决问题：黑白线稿粗线变双线（ISSUE_lineart_double_lines.md）

## 一、核心架构变更

V2.1 建立了**输入语义分叉**架构：

```
图片
  │
Input Classifier (auto detect)
  │
  ├─ 彩色填充图  → Region → SharedBoundary (V2.0/V2.1 原有逻辑, 不动)
  └─ 黑白线稿    → Stroke → Skeleton (中心线)  ← V2.1 新增
```

**关键原则**：彩色图是 Region 问题（面→面边界），黑白线稿是 Stroke 问题（线→线中心），二者不能共用同一几何语义。Line Art 模式**禁止**使用 SharedBoundaryExtractor。

## 二、修改/新增文件

### 新增 `backend/lineart/` 模块（6 个文件）

| 文件 | 职责 | 复用开源 |
|------|------|----------|
| `detector.py` | 自动线稿检测（颜色数/饱和度/黑白比例/灰度标准差） | NumPy |
| `preprocess.py` | BW 二值化（Otsu + 中值去噪 + 形态学闭运算 + 边界清除） | OpenCV |
| `skeleton.py` | 骨架化（默认 skeletonize，可选 thin/medial_axis） | **scikit-image** |
| `graph.py` | 骨架→图（8 邻域：endpoint/normal/junction，Edge 有序点串） | NumPy |
| `pruning.py` | 毛刺修剪（末端短分支迭代删除，默认 0.8mm，可开关保留细小线段） | NumPy |
| `pipeline.py` | 线稿管线（坐标转换→简化→Bezier→G0/G1合并→验证→SVG/DXF/IBL） | 复用现有 CurveSimplifier/BezierFitter/CurveMerger/CurveValidator/全部 Exporters |

## 三、Line Art Pipeline 流程

```
原图 (PNG/JPG bytes)
  ↓ cv2.imdecode
BW 二值化 (Otsu 自动阈值 + 中值去噪 + 闭运算 + 边界1px清除)
  ↓ mask (True=黑线前景)
Skeletonize (skimage.morphology.skeletonize)
  ↓ 单像素宽骨架
Skeleton Graph (8邻域: 1=endpoint, 2=normal, ≥3=junction)
  ↓ Node + Edge(有序点串)
Spur Pruning (迭代删除 <0.8mm 末端分支, 可开关)
  ↓ 修剪后骨架
坐标转换 (x=px*scale, y=(H-py)*scale)
  ↓ mm 坐标
简化 (Douglas-Peucker, 复用 CurveSimplifier)
  ↓
Bezier 拟合 (复用 BezierFitter)
  ↓
曲线连续性合并 (G0≤0.01mm + G1≤3°, 4端点自动翻转, 复用 CurveMerger)
  ↓
工程验证 (自交/线距/小半径, 复用 CurveValidator)
  ↓
导出 SVG / DXF / IBL / JSON (复用全部 Exporters)
```

Debug 输出（`debug_dir` 配置）：
- `01_original.png` 原图
- `02_binary.png` 二值 Mask
- `03_skeleton.png` 骨架
- `04_pruned_skeleton.png` 修剪后骨架
- `05_vector_curve.svg` 矢量曲线
- `06_final_preview.svg` 最终预览

## 五、是否还有双线？

**没有。** 通过叠加对比图（红色生成曲线 + 灰色原图）目视确认：
- 问号：单条中心线沿笔画中间
- 头顶呆毛：单条中心线
- 头顶弧线：单条中心线
- 眼睛椭圆：每个椭圆单条闭合中心线
- 身体轮廓：单条中心线
- 脚、尾巴、底部基线：单条中心线

V2.0 的"粗黑线→左右两条边缘平行线"问题已彻底解决。

## 六、是否还有明显毛刺？

修剪了 27 条末端短毛刺（<0.8mm）。剩余少量短分支主要是：
- 线稿本身的细节（如脚趾、嘴角）
- 骨架化在交叉区域产生的微小分支

可通过增大 `min_spur_length_mm`（默认 0.8mm）进一步修剪，或开启 `keep_fine_segments=True` 保留全部细小线段。

## 八、已修复的关键 Bug

### Bug 1：异常斜穿直线（141mm 对角线）
- **现象**：用户线稿输出中有一条从左上角到右下角的异常长直线
- **根因**：原图顶行和左列有 1px 深色边框（灰度 23-28），Otsu 二值化当成前景；skeletonize 后 L 型边框在角点被 8 邻域 walk_edge 错误连接成对角线
- **修复**：`preprocess.py` 二值化后清除图像边界 1px（`border_crop_px=1`，可配置）
- **验证**：修复后异常曲线消失，curve 数 552→551

### Bug 2：中文路径 PNG 保存失败
- **现象**：OpenCV `imwrite` 不支持中文路径，调试图 PNG 保存失败（SVG 正常）
- **修复**：`pipeline.py` `_save_debug` 改用 `cv2.imencode` + `ndarray.tofile`

## 九、已知问题 / 后续优化方向

1. **线距冲突数偏高（1553）**：线稿模式产生 551 条曲线，密集区域（如眼睛、脚趾）线距<0.8mm。这是线稿本身的特点，非 bug。后续可考虑：
   - 线稿模式使用更小的默认最小线距（如 0.3mm）
   - 或在骨架阶段合并过近的平行骨架

2. **曲线数量偏多（551）**：骨架化产生较多细碎边。后续可优化：
   - 更强的骨架简化（在 graph 阶段合并共线短边）
   - 或增大简化容差

3. **medial_axis 未启用**：规格书建议 medial_axis 作为 V2.2 实验选项，当前默认 skeletonize。UI 可未来增加"中心线算法：Skeletonize / Medial Axis"选择。

4. **UI 未增加线稿模式开关**：规格书要求 UI 增加生成模式选择（普通SVG/掐丝珐琅/仅轮廓/线稿）和调试图层显示（原图/Mask/Skeleton/最终曲线）。当前后端已支持 `gen_mode=auto/lineart/color`，前端 UI 待接入。

5. **彩色图自动检测可能误判**：低饱和度的彩色图（如淡彩）可能被误判为线稿。当前策略是不确定时优先彩色模式，降低误判风险。

## 十、使用方式

```python
from backend.pipeline import CloisonnePipeline

# 自动检测（默认）
pipe = CloisonnePipeline({})  # gen_mode 默认为 auto
result = pipe.run(image_bytes, output_width_mm=100)

# 强制线稿模式
pipe = CloisonnePipeline({"gen_mode": "lineart"})

# 强制彩色模式
pipe = CloisonnePipeline({"gen_mode": "color"})

# 线稿模式参数
pipe = CloisonnePipeline({
    "gen_mode": "lineart",
    "min_spur_length_mm": 0.8,      # 毛刺修剪阈值
    "keep_fine_segments": False,     # 保留细小线段
    "skeleton_method": "skeletonize", # skeletonize/thin/medial_axis
    "border_crop_px": 1,             # 边界清除像素
    "debug_dir": "path/to/debug",    # 调试图输出目录
})
```
